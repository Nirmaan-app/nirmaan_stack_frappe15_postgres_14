## BoQ pricing-editor rules (full)

**BoQ pricing-editor quick rules (full detail: plan "## Phase 5 Pricing Editor -- slice detail"):**
- **Single-editor lock:** deterministic PK `sha1(boq \x00 sheet_name \x00 int(version))`; reject marker `BOQ_PRICING_LOCKED`; `LOCK_STALE_SECONDS = 300` (5-min edit-driven expiry, NO heartbeat / NO release endpoint / NO socket); acquire-on-first-edit; a lock REJECT mutates NOTHING (the acquire slots after the cell-resolve + before any freeze/insert). `api/boq/wizard/pricing_lock.py` `acquire_or_refresh`.
- **Priceability gate (§6, a DELIBERATE recorded loosening of "server always rejects"; ASYMMETRIC since the Preamble qty-bearing slice):** a rate is editable iff **override OR `node_type == "Line Item"` (ALWAYS) OR (`node_type == "Preamble"` AND the row is QTY-BEARING)**. **The Preamble/Line-Item asymmetry is owner-locked** (a zero-qty Line Item is a valid rate-only line -> editable; a zero-qty Preamble -- nearly all Preambles -- is read-only). "Other" (and a null node_type) is non-priceable. **QTY-BEARING here = "qty ANYWHERE" ("Definition A"): the scalar qty OR any per-area qty is finite non-zero -- DELIBERATELY LOOSER than `priceability.isPriceableLine` (which restricts to a RATE-COLUMN area; that drives the flags/priced-count/rollup). The two definitions coexist ON PURPOSE -- the gate answers "can I edit this row?", the flags answer "does THIS area need a rate?" -- do NOT align them.** REJECT-by-default / ACCEPT-on-asserted-override (`allow_non_priceable`, unlocking BOTH a zero-qty Preamble AND a non-priceable type), enforced BOTH frontend (`PricingGrid.isRateEditableRow` / `isRowQtyBearing` -- a self-contained `isNonZeroNum` copy in PricingGrid, NOT imported from priceability, to keep the one-way dependency) and server (`save_cell_price`: `_node_is_qty_bearing` reads the node's scalar `qty` [now fetched by `_resolve_committed_cell`] + its `BOQ Node Qty By Area` children, the child read firing ONLY for a Preamble-without-override). The override-priced "needs review" anomaly is DERIVABLE (`priced && !priceable`) -- NO marker field on BoQ Cell Pricing (the amber marker still keys on `isPriceableType` TYPE, so an override-priced zero-qty Preamble renders emerald not amber -- a known cosmetic nuance, not a gate defect). Phased build (Phase 0 → 7) — don't implement Phase N+1 functionality while working in Phase N. Phase 2 sub-phase split: 2a → 2b.1a → 2b.1b → 2b.2 (A1, A2, A3, B) → 2c.
- **Amount-formula builder F1 (BACKEND storage, plan §"Formula Builder F1"):** NEW doctype **`BoQ Cell Amount Formula`** (per-COLUMN, per-committed-version; autoname `BAMF-.YY.-.#####`; mirrors BoQ Cell Pricing's freeze-and-supersede triple `formula_version`/`is_current`/`defined_at` + `is_finalized`). Identity = (boq, sheet_name VERBATIM #152, committed_version, target_value_field, target_value_key, target_rate_subkey). **`target_value_key` NULL = the area-WILDCARD logical-column DEFAULT (or "scalar"); a concrete area = a PER-AREA OVERRIDE -- nullability IS the discriminator (no extra field).** `formula` = a token-tree JSON: operator `{op:"+"|"*",operands:[...]}` or leaf `{ref:{value_field,value_key,rate_subkey}}` -- **NO literal node** (literals barred); operand refs first-class (F2 builds the dep-graph without parsing). F1 STORES + SERVES only -- NO evaluation, NO cycle-check (both F2). Endpoints in `pricing.py`: `save_amount_formula` (AMOUNT-target gate via `_build_column_descriptors`; structural-validate; lock after target-resolve+validate, before freeze/insert; blank formula CLEARS) + `get_sheet_amount_formulas` + a `column_formulas` PER-COLUMN key merged into `get_priced_rows` (NOT per-row). The grid-display swap (F4) replaces `PricingGrid.findPairedRateDescriptor`; subtotal rollup (`pricingRollup.ts`) is a SEPARATE cross-row surface, untouched.
- **Mandatory amount-formula gate (plan §"Mandatory amount-formula gate"):** amount formulas are now **MANDATORY before pricing** -- this **REVERSES the F1-F4 "formula optional" property**. A rate is editable ONLY when the sheet is **formula-COMPLETE**: **every amount column has a declared covering formula**, per the per-COVERAGE predicate (an area-WILDCARD default `target_value_key=null` covers ALL its per-area columns sharing that (value_field, rate_subkey); a sheet with **zero** amount columns is **trivially complete**). The gate is **ABSOLUTE -- the `allow_non_priceable` override does NOT bypass it** (override loosens only the type/qty axis). Server: `pricing.py` `_sheet_formulas_complete(boq, sheet, version)` (over `_committed_amount_descriptors` + `_current_formula_records`) built on the SHARED `_formula_target_matches_column` primitive (the override-or-wildcard rule, also now backing `save_amount_formula`'s target-gate -- one source of truth, via `_formula_covers`). The throw (`title="Formulas incomplete"`) sits in `save_cell_price` **AFTER `_resolve_committed_cell`** and **OUTSIDE/BEFORE the `if not _coerce_bool(allow_non_priceable):` block** (so override can't skip it) and BEFORE the lock/freeze/insert (**reject-mutates-nothing**). `save_amount_formula` is **NOT** gated (declaration must work while rates are locked). Frontend: `priceability.areFormulasComplete(columnDescriptors, columnFormulas)` (REUSES `pickFormula` -- the SAME resolution `evaluateAmountCell` uses, no drift) -> a per-SHEET boolean ANDed into the grid's rate gate **OUTSIDE `isRateEditableRow`** (`onSaveRate && formulasComplete && isRateDescriptor(d) && isRateEditableRow(row, override)`) + added to `pricingRowPropsAreEqual` (memo-safe), plus a "Declare amount formulas to enable rate entry." banner. **MAGNITUDE (intended):** existing canonical sheets with zero/partial formulas are rate-LOCKED until declared (145 Electrical 1/2, HVAC 1/2, Fire Fitting 0/2, VRF 0/9 -> locked; 145 FAS 0-amount-cols + 150 low side 1/1 -> editable; VRF's 9 per-area cols unlock via ONE wildcard default per kind).
